Architecture & Compliance Specification

Technical reference for verbal-authorization verification in CI/CD pipelines.

1. The Problem Space: Undocumented Verbal Claims

Autonomous coding agents (Devin, SWE-agent, OpenHands) push commits and open PRs with claims of informal human approval (e.g. "As confirmed with @sarah_dba during standup, this is safe to drop the legacy v1_accounts table").

Static linters, automated tests, and CI/CD pipelines only check code diffs and digital artifacts. Because verbal authorizations have no digital audit trail, telephony verification of the named person is the only viable out-of-band verification mechanism.

2. Interrogation Methodology: Free Recall First

The CALL-E telephony prompt uses a forensic interview structure: 

1. Disclose call context: Automated change-control audit for repository.
2. Request unprompted recall: "What did you discuss about the accounts table today?"
3. Conditional claim confrontation: Only read back specific agent claims if unprompted recall does not address it.

Leading with "Did you approve X?" produces a reflexive confirmation bias. Free recall isolates confabulations and fabricated authorization.

  verify-claims:
    runs-on: ubuntu-latest
    steps:

          python scripts/run_verification.py \
            --title "${{ github.event.pull_request.title }}" \
            --body "${{ github.event.pull_request.body }}" \
            --pr-ref "${{ github.repository }}#${{ github.event.pull_request.number }}" \
            --post-to-github
