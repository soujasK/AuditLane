Architecture & Compliance Specification

Technical reference for verbal-authorization verification in CI/CD pipelines.

1. The Problem Space: Undocumented Verbal Claims

Autonomous coding agents (Devin, SWE-agent, OpenHands) push commits and open PRs with claims of informal human approval (e.g. "As confirmed with @sarah_dba during standup, this is safe to drop the legacy v1_accounts table").

Static linters, automated tests, and CI/CD pipelines only check code diffs and digital artifacts. Because verbal authorizations have no digital audit trail, telephony verification of the named person is the only viable out-of-band verification mechanism.

2. How It Works

PR text
   |  rule-based regex extraction (no LLM, no external calls)
   v
Claim(authorizer, claim_text, subject)
   |  look up authorizer in the trusted phonebook directory
   |  (never derived from the PR text itself, to prevent spoofing)
   v
CALL-E places a real phone call to that number
   |  free-recall interview, then entailment scoring of the reply
   v
Verdict: VERIFIED / BLOCKED / NEEDS_HUMAN_REVIEW

If the authorizer's answer references a second person's approval (e.g. "the security lead already signed off"), the same pipeline calls that person too, up to a configurable hop limit, before deciding.

3. Decision Policy — Deliberately Simple, Fails Closed

The policy is explicit rules, not a learned model, so every outcome is explainable:

  • BLOCKED — the authorizer explicitly denies the claim, or contradicts it with confident entailment.
  • VERIFIED — every hop in the chain confirmed the claim with confident entailment. The narrow, hard-to-reach case, by design.
  • NEEDS_HUMAN_REVIEW — anything else: no phone on file, unreachable, hedged or low-confidence, chain too long. It never guesses — ambiguity always routes to a human, never to a merge.

4. Interrogation Methodology: Free Recall First

The CALL-E telephony prompt uses a forensic interview structure: 

1. Disclose call context: Automated change-control audit for repository.
2. Request unprompted recall: "What did you discuss about the accounts table today?"
3. Conditional claim confrontation: Only read back specific agent claims if unprompted recall does not address it.

Leading with "Did you approve X?" produces a reflexive confirmation bias. Free recall isolates confabulations and fabricated authorization.

5. Every Surface Runs the Same Verification Engine

telephony-gate is a Claude Code hook — every dangerous Bash command an agent tries to run is intercepted here, automatically, before it executes. audit_pr runs the same way, just at a different point in the pipeline: it's wired into the GitHub Actions workflow (see section 6), so it fires automatically on every pull request, regardless of which agent — or human — opened it, with no dashboard step involved. Voice Sandbox, below, is the one surface you trigger directly from this dashboard — a raw test call for demoing the mechanism itself, with no danger-pattern matching or claim extraction involved. All three, plus an MCP server for direct agent integration, call into the identical Python verification pipeline — there's exactly one code path that ever places a real call.

6. GitHub Actions Integration Snippet

name: AuditLane
on: [pull_request]
jobs:
  verify-claims:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Audit verbal authorization
        run: |
          python scripts/run_verification.py \
            --title "${{ github.event.pull_request.title }}" \
            --body "${{ github.event.pull_request.body }}" \
            --pr-ref "${{ github.repository }}#${{ github.event.pull_request.number }}" \
            --post-to-github
